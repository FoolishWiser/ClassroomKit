# 版本与发布

## 发布策略

从 0.3.0 起**只发正式版**：版本号是三段 SemVer（`0.3.0` → `0.3.1` → `0.4.0`），不再用 `-pre.N` 做对外发布。

- 打补丁 / 加功能 → 升修订号或次版本号，只改 `Directory.Build.props` 一处；
- 每个正式版在 Releases 上都会成为「Latest」，装了就自动收到下一个正式版的升级提示；
- `-pre.N` 的能力还在（构建脚本与升级比较都支持），只留给本地临时验证，不进正式流程。

## 版本号只有一个来源

所有版本号都从仓库根的 `Directory.Build.props` 来：

```xml
<Version>0.3.0</Version>
<AssemblyVersion>0.3.0.0</AssemblyVersion>
<FileVersion>0.3.0.0</FileVersion>
```

- **`Version`**：给人看、给升级比较用。正式版三段（`0.3.0`）。
- **`AssemblyVersion` / `FileVersion`**：只取三段（`0.3.0.0`）。.NET 不允许 AssemblyVersion 带后缀，所以预发布只体现在 `InformationalVersion`（MSBuild 会自动写成 `0.3.0+<commit>`）。
- 各 csproj **不要再写 Version/AssemblyVersion**；写了两边会打架。
- 插件清单 `src/ClassroomKit.ClassIsland/manifest.yml` 的 `version` 必须与 `$(Version)` 一致，构建时由 `VerifyManifestVersion` 目标校验，不一致直接编译失败（避免装上去显示旧版本）。

运行时取版本用 `AgentRuntime.DisplayVersion()`：读 `AssemblyInformationalVersion` → 砍掉 `+commit` → 读不到才回退三段版本。

## 版本比较规则（SemVer）

`UpdateVersion` 按 SemVer 比较，不是简单字符串比：

| 比较 | 结果 |
| --- | --- |
| `0.3.0` vs `0.3.0-pre.1` | 正式版更大 |
| `0.3.0-pre.2` vs `0.3.0-pre.10` | 按数字段比，`pre.10` 更大（不是字典序） |
| `0.3.0-pre.1` vs `0.3.0-pre.1.1` | 前缀相同，段数多的更大 |
| `0.2.10` vs `0.3.0-pre.1` | 先比主次修订号，0.3.0 更大 |
| `+build` 后缀 | 忽略 |

所以客户端不管装的是 0.2.x、开发期的 `-pre.N`，还是上一个正式版，都能正常收到 `0.3.0` 这类新正式版的升级提示。

## CI 排查小开关

打 MSI 这一步失败时，工作流会把这一步的完整输出（含 `wix build` 的报错）推到 `ci-logs` 分支的 `ci-msi-step.log`：

```bash
git fetch origin ci-logs && git show origin/ci-logs:ci-msi-step.log
```

成功时不会推，排查完可以删掉这个分支（`git push origin --delete ci-logs`）。

## MSI 内部的版本号

Windows Installer 的 `ProductVersion` 只认纯数字（最多 4 段），所以 `build-msi.ps1` 会把预发布后缀折成第 4 段：

| 对外版本 | MSI 产品版本 | 说明 |
| --- | --- | --- |
| `0.3.0-pre.4` | `0.3.0.4` | 只在开发期临时用：`-pre.N` 折成第 4 段 |
| `0.3.0` | `0.3.0` | 正式版，原样 |
| `0.3.1` | `0.3.1` | 补丁版，数字比 `0.3.0` 大，直接覆盖升级 |

文件名保留完整版本号（`ClassroomKit-0.3.0-x64.msi`），只有「应用和功能」里显示的版本是数字形式。
`ProductCode` 按**完整**版本号算，所以 `0.3.0 → 0.3.1`（或开发期的 `pre.3 → pre.4`）都是不同产品，由 `MajorUpgrade` 移除旧版，不会残留两行。

## 本地构建

Windows（完整，出 MSI + zip + cipx）：

```powershell
./scripts/build.ps1 -Version 0.3.0
./scripts/build-msi.ps1 -Version 0.3.0 -Dist dist
dotnet publish src/ClassroomKit.ClassIsland -c Release -p:Version=0.3.0 -p:CreateCipx=true
```

Linux / macOS（只能编代码和插件，**打不了 MSI**，WiX 仅 Windows）：

```bash
/root/.dotnet/dotnet build src/ClassroomKit.ClassIsland/ClassroomKit.ClassIsland.csproj
/root/.dotnet/dotnet publish src/ClassroomKit.ClassIsland -c Release -p:CreateCipx=true -p:GenerateHashSummary=false
```

`GenerateHashSummary` 默认 true，会调 `pwsh generate-md5.ps1` 生成插件校验和；没有 pwsh 的机器要显式关掉，否则报 `MSB3073 … exited with code 127`。产物在 `src/ClassroomKit.ClassIsland/cipx/ClassroomKit.ClassIsland.cipx`。

跑测试（跨平台，零依赖）：

```bash
/root/.dotnet/dotnet run --project tests/ClassroomKit.Tests -c Release
```

## 正式发布

1. 改 `Directory.Build.props` 的 `Version`（插件 manifest 不用手动改，CI 会写）。
2. 提交并打 tag：`git tag v0.3.0 && git push origin v0.3.0`，或手动跑 `.github/workflows/build.yml` 并填 version。
3. CI（windows-latest）依次：跑测试 → WiX 打 MSI → 打 zip → 打 cipx（同时把 manifest 版本改成同一版）→ 校验三个产物 → 建 Release。
4. 产物：
   - `ClassroomKit-<版本>-x64.msi`（推荐安装）
   - `ClassroomKit-<版本>-win-x64.zip`（绿色版，不含 cipx）
   - `ClassroomKit-<版本>.cipx`（ClassIsland 2.1 插件）
5. 正式版（版本号不带 `-`）会自动成为该仓库的 **latest**；万一临时打了 `-pre.N`，CI 仍会勾 prerelease，不会顶掉 latest。

## 兼容性

- 守护与插件同版本发布，但**插件向后兼容**：请求同时带 `X-Token` 头和 `?t=` 参数，旧守护的鉴权也认。
- 插件要求 ClassIsland **2.1.x**（SDK 2.1.0.1，清单 `apiVersion 2.0.0.0`）。1.6/1.7 用零代码自动化（见 `ClassIsland-接入.md`）。
- 配置带 `schemaVersion`：0.3.0 把结构版本升到 2（新增 `hosts` 段），旧 `config.json` 只补默认值、**不改**已保存的 SSID/密码/令牌；新装机器才用「计算机名 + 随机 8 位密码」。
