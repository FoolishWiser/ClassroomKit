## 3. 现场证据

### 3.1 20:37 故障现场（`diag-now.ps1`）

```
state      = On
clients    = 0
ssid       = [888]
passphrase = [12345678] len=8      <-- 与脚本设定 seewo8888 不一致
band       = TwoPointFourGigahertz
profile    = 以太网
AP 适配器  = 本地连接* 10  ifIndex 18  Up（Microsoft Wi-Fi Direct Virtual Adapter #2）
RX=0  TX=130998
```

- 没有客户端、`RX=0` → 手机根本没完成过任何帧交换；结合"能看到 888"，说明射频在发信标但连接阶段（联合/握手）失败。
- 自启任务在 07:16 就 `FAILED`，等于整天的热点状态是「07:16 那次残留 + 用户在设置里手动点过的结果」，不可控。

### 3.2 密码漂移的硬证据

1. 20:39:55 我们写入 `seewo8888`，脚本回读 `passlen=9 passmatch=True`；
2. 20:40:04 出现**没有我们参与的** 8008（停止承载网络），20:40:06 8005/8006（重新启动）；
3. `C:\ProgramData\Microsoft\Wlansvc\Profiles\Interfaces\{DDE24943-…}\{60A09101-…}.xml` 的 `LastWriteTime = 2026-11-17 20:40:06`；
4. 之后 `GetCurrentAccessPointConfiguration().Passphrase` 回到 `12345678`（8 位）；
5. 3 秒后（20:40:13 起）连续三次 `11005` 成功、三台手机连上——说明手机存的就是 `12345678`。
6. `SystemSettings.exe` 自 07:16:50 起常驻（用户此前在「设置 → 移动热点」里改过密码）。

### 3.3 11/16 的"假启动"证据（复核仍然成立）

- 手机能看到希沃自己的 `DIRECT-KVDESKTOP-B177447msmC`（`bc:fa:b8:bb:62:b9`，ch11，56–62%），本机也能扫到 → 射频收发正常；
- 但 888 在本机扫描里**始终不出现**，AP 适配器 `RX=0`；
- 只有 `Restart-NetAdapter -Name WLAN` 才能真正把它救回来（11/16 与 11/17 两次都是这个动作生效）。

> ⚠️ 反面教训：**不能用本机 `netsh wlan show networks` 判断 888 在不在广播**。11/17 20:40 三台手机连着、能上网，本机自扫依然没有 888（STA 扫描不列自己这张网卡起的 GO）。判断依据只能是 `ClientCount` 和 AP 适配器 `RX/TX` 计数。

## 4. 根因分析

### 4.1 主因：两个"配置主人"互相覆盖（本次）

- 一侧是脚本（历史上默认 `seewo8888`），另一侧是 Windows 自带「移动热点」设置（存 `12345678`）。
- Windows 的设置程序只要开着，就会在适当时机把自己的存取点配置重新应用（`NetworkOperatorTetheringManager.ConfigureAccessPointAsync`），并在需要时停/启承载网络。20:40:04 的停/启就是它做的。
- 对手机而言，这表现为「列表里有 888，输密码却报错 / 一直转圈」——因为密码在两次尝试之间被换掉了。

### 4.2 次因：8821CU 的 soft-AP "假启动"（11/16 以来一直在）

- 驱动是 2019 年的 `1030.38.328.2019`，`Hosted network supported: No`，只能走 Wi-Fi Direct GO（`WLANAPProfile` / `WFD_GROUP_OWNER_PROFILE`）。
- 触发条件：USB 选择性暂停/设备电源管理、第三方 Wi-Fi Direct GO（希沃传屏 + SeewoLink）抢同一射频、以及反复 Stop/Start 后驱动内残留状态。
- 表现：WinRT 报 `TetheringOperationalState=On`、虚拟适配器 Up、IP 正常，但空口不发信标，`RX` 恒为 0。
- 唯一可靠的恢复手段：`Restart-NetAdapter -Name WLAN`（复位后再 `StartTetheringAsync`）。

### 4.3 加剧：自启任务把"还在启动中"判成失败

- v1 脚本 `StartTetheringAsync` 之后固定 `Sleep 4` 就检查状态；复位网卡后 WLAN 栈需要 10–30 秒才 `On`，于是 `state=InTransition` → 判定 FAILED（`LastTaskResult=1`）。
- 后果：本该"每次登录都把热点修好"的机制失效，只能靠用户手动点设置，进一步加剧 4.1 的漂移。

### 5.1 `Hotspot-Start.ps1` v3 的关键变化

| 变化 | 解决的问题 |
| --- | --- |
| `StartTetheringAsync` 后**轮询最多 30 秒**等 `state=On` 且 Wi-Fi Direct 适配器 Up | 4.3 的 `InTransition` 误判 |
| 失败自动**再来一轮**（中间复位网卡） | 单次失败不再需要人工介入 |

| 结束时校验并打印 `passmatch`；显式密码被系统覆盖时判失败 | 把"静默失败"变成可见失败 |

## 7. 遗留风险与建议

| 风险 | 影响 | 建议 |
| --- | --- | --- |
| 8821CU 2019 年驱动在 soft-AP 下仍偶发 `0x48005` 四次握手超时 | 手机第一次连接可能失败 1–3 次，重试即成功 | 升级 Realtek 8821CU 驱动（Win10 2004 之后的版本）；升级前先导出当前 `oem19.inf` |
| 有人再在「设置 → 移动热点」里改密码 | 手机端旧密码立刻失效 | 统一约定：**密码只在 Windows 设置里改**（脚本不显式传 `-Passphrase`，会自动跟随）；或在脚本里显式传参并只跑脚本 |
| 用户手动点「移动热点」开关 | 会触发停/启，短时间踢掉在线设备 | 日常让登录任务处理；必须手动时用 `Hotspot-Start.ps1` |
| 希沃传屏（`ExceedShare`）与 `SeewoLink` 仍占同一射频 | 少数情况下抢 GO 导致"假启动" | 需要稳定时跑 `-KillScreenShare`；`SeewoLink` 实测可共存，暂不动 |
| 本机扫描看不到自己的 888 | 容易误判"热点没广播" | 判断依据固定为 `ClientCount` + AP 适配器 `RX/TX`（已写进 README） |
| 单网卡 + USB 供电/节电 | 长期运行可能再次挂起 | 电源项已固化（USB 选择性暂停关、`PnPCapabilities=24`、`MSPower_DeviceEnable=False`），脚本每次运行会复核 |

## 8. 复发时的处置顺序（30 秒判断法）

```powershell
# 1) 看现状（不需要管理员）：state / clients / 生效密码
powershell -NoProfile -ExecutionPolicy Bypass -File C:\Users\seewo\Documents\hotspot\diag-now.ps1
```

- `clients > 0` 但手机连不上 → 手机侧问题（忘记网络重连）；
- `state=On`、`clients=0`、`passphrase` 与预期不符 → **密码漂移**：`Hotspot-Start.ps1 -Passphrase 12345678`；
- `state=On`、`clients=0`、`RX=0`、手机列表里也看不到 → **假启动**：`Hotspot-Reset.ps1`（复位网卡）；
- `state=Off` 或任务失败 → `Hotspot-Start.ps1 -KillScreenShare -HardReset`（管理员）；
- 以上都无效 → 换频段 `-Band FiveGigahertz`，或升级网卡驱动。
