# 原理与限制

## 1. 热点是怎么开的

用 Windows 自带的移动热点引擎（WinRT）：

```csharp
var profile = NetworkInformation.GetInternetConnectionProfile();
var mgr = NetworkOperatorTetheringManager.CreateFromConnectionProfile(profile);
await mgr.StartTetheringAsync();                  // 开
await mgr.ConfigureAccessPointAsync(config);      // 改 SSID/密码
mgr.TetheringOperationalState                     // On / Off / Starting
mgr.MaxClientCount                                // 系统允许的最大客户端数
```

- Win32 程序直接调 WinRT **不需要** `wiFiControl` 清单能力（那个只约束 UWP/AppContainer），所以不做 MSIX 打包。
- `CreateFromConnectionProfile` 必须拿到「有 Internet 的连接配置文件」——这决定了为什么不能把它做成 Windows 服务（见 §4）。
- `netsh wlan hostednetwork` 是另一套东西，Win10 已弃用，Intel AX210 上 `netsh wlan show drivers` 直接显示「支持的承载网络: 否」。本工具完全不用它。

## 2. 8 台上限是怎么破的

`MaxClientCount` 默认 8，是移动热点自身的设计默认值（早期 hosted network 遗留），**不是网卡驱动的硬限**。

- 注册表键：`HKLM\SYSTEM\CurrentControlSet\Services\icssvc\Settings`，值 `WifiMaxPeers`（REG_DWORD）
- 改完必须重启 `icssvc` 服务，让上层重新读

实测（Intel AX210，Win10 19045）：

```text
写入前：MaxClientCount = 8
写入 WifiMaxPeers=16 并重启 icssvc 后：MaxClientCount = 16
```

面板上的「系统上限 16 台」就是读的这个值；「注册表放宽 目标 16」是配置里希望写进去的值。低于目标时会显示黄色告警「系统上限 X 台，低于目标 Y 台」。

> 写入需要管理员：`--fix-peers`（面板按钮会提权并弹一次 UAC，结果写到 `C:\ProgramData\ClassroomKit\last-fix.txt`）。

## 3. 「无设备 5 分钟自动关」必须显式关掉

Windows 默认 `IsNoConnectionsTimeoutEnabled() = true`：热点开着但没设备连，5 分钟后自己消失。教室里热点常常在老师进教室前就开着、或者课间没人连，所以必须关：

```csharp
NetworkOperatorTetheringManager.DisableNoConnectionsTimeout();   // 静态方法
```

坑：**这是静态方法**。用实例调 `IsNoConnectionsTimeoutEnabled()` / `GetTetheringCapability()` 会抛 `MethodNotFound`（反射实测），早期版本就是因此调反了方向、热点照旧 5 分钟消失。

## 4. 为什么不做成 Windows 服务

服务跑在 Session 0，没有登录用户；而 `NetworkInformation.GetInternetConnectionProfile()` 和移动热点绑定的是「当前用户的连接配置文件」，Session 0 里拿到的是空 → 起不来。ClassIsland 恰好运行在用户会话里，但它是普通权限、且要等界面和课表加载完（10–40 秒），比开机自启慢得多。

结论：**用户级常驻进程 + 登录自启计划任务**（延迟 8 秒、Users 组、最低权限、失败每分钟重试 3 次）。代价是「不登录就没有热点」——教室场景里老师一定会登录，可接受。

## 5. 为什么面板是本地网页

- 不用 `HttpListener`：非管理员需要预先注册 URL ACL，部署多一步、还原卡上还容易丢。
- 不用 Kestrel：自带服务器要多带几 MB 依赖，还要处理绑定与证书。
- 自己写一个只绑 `127.0.0.1` 的极简 HTTP/1.1（一问一答、`Connection: close`、16 KB 请求头上限、1 MB 请求体上限、15 秒超时），配合手写 HTML/CSS/JS（无框架、无 CDN，离线可用），令牌鉴权走 `?t=` 或 `X-Token`。

面板只在回环上，**局域网里的学生打不开**。

## 6. 稳定性设计

| 场景 | 行为 |
| --- | --- |
| 网卡自己把热点关了 / 被第三方工具关了 | 15 秒巡检发现 `OperationalState != On` → 重新开 |
| SSID 或密码被改 | 对比配置与当前值，不一致就 `ConfigureAccessPointAsync` 改回 |
| 开热点失败 | 退避 60 → 300 → 1800 秒，成功即清零 |
| 网线拔掉 | 状态「等待上行」，不反复重试；插回 15 秒内恢复 |
| 上行是 Wi-Fi | 拒绝开热点（会把仅有的无线占掉），除非面板勾了「允许 Wi-Fi 当上行」 |
| 启动了两份 | 全局互斥体 `Global\ClassroomKit.Agent`，第二份发个 `ensure` 就退出 |
| 面板按钮点了没反应 | 点按钮会唤醒巡检（信号量），不用等 15 秒 |
| 日志 | 内存环形 400 条 + 按天写盘，保留 14 天，写盘失败不影响守护 |

## 7. 资源占用实测

| 指标 | 数值 |
| --- | --- |
| 私有内存 | 约 56 MB（工作集约 152 MB，多数是共享的运行时页） |
| 空闲 CPU | 60 秒采样 0.06 秒 ≈ 0.1%（单核） |
| 单文件大小 | 约 70 MB（自包含，目标机零依赖） |
| 启动到热点可用 | 约 1 秒（进程内）；登录自启另加 8 秒延迟 |

GC 配置了 `System.GC.ConserveMemory=5`，常年开机不会慢慢涨。

## 8. 已知限制

1. **真实 10 台并发没有实测**：手上没有足够的真实终端。注册表层面 16 台已验证（`MaxClientCount=16`），但网卡/AP 固件在真实并发下的表现要按学校实际设备验收（建议先在一个教室试 10–12 台）。
2. **上限仍受驱动/固件约束**：注册表放宽到 16 不代表任何网卡都能跑 16 台；20 台以上不保证，不建议把 `targetClients` 设超过 16。
3. **不登录就没有热点**：见 §4。
4. **只支持一台机器一个热点**：没有集中管理/批量下发，多教室逐台部署（可用 `rebuild.ps1` + 还原卡策略简化）。
5. **只能走系统移动热点引擎**：不支持 WPA3-only、不支持指定 5GHz 信道（`band` 字段目前只写配置，未作用到系统 API）。
6. **强力卸载是拉起 BCUninstaller**：BCU 需要自备便携版放到 `BCU\` 子目录（Apache-2.0，可随包分发）；没放时按钮会提示路径。
7. **面板没有远程访问**：设计如此。
8. **“有 IP 没网关”只在单测里验证过**：这条兜底（专治“学校只给 IP”和默认路由抖动）在真机上需要有第二块没配网关的网卡才能端到端复现，本机没有这种网卡；逻辑由 17 项选择器单测覆盖，真机验收时若遇到请重点看面板「上行」是否显示“无网关”且热点仍为“运行中”。
9. **无外网兜底不等于能上网**：兜底只是让学生能连上、访问一体机上的课件/共享目录；没有 WAN 就没有外网，面板会标注「无外网」。

## 9. 板书自动化为什么是「坐标 + 像素」，以及它有多脆

ClassInX 6.0.9 是 Qt 5.15 应用，UIA 树里一个子控件都没有（`FindAll(Children)` 返回 0），所以拿不到按钮的可访问性对象，只能：

1. 按窗口矩形 + 相对坐标点按钮（`保存至本地` = (667,78)，`保存` = (125,258)……）；
2. 按像素判勾选状态（复选框中心 11×11 取样：有绿填充或亮白勾即视为已勾）。

代价很直白：**换皮肤、改 DPI、按钮移位都会失准**。所以坐标单独存在 `C:\ProgramData\ClassroomKit\ui-recipe.json`，`--probe-classin` 可以重新采样一次；匹配时按 6% 容差容忍小幅缩放，真对不上就明确报「界面可能变了，请重新探测」，不会乱点。速度靠全轮询而不是固定 sleep（实测 1.76 秒，其中 0.8 秒是 ClassInX 自己弹的三个「文件已存在」确认框）。

## 10. 冲突提示的判定口径

- **悬浮窗**：ClassInX = 该进程的 `TOPMOST + TOOLWINDOW` 窗口且面积 < 30% 屏；希沃白板 = `EasiNote` 进程的 `LAYERED|TOPMOST` 小窗。
- **全屏**：窗口矩形≈整块屏幕（8px 容差）。WPS 放映**不置顶**，ClassInX 板书全屏也不置顶，所以判定不能只看 topmost，必须按「矩形 + 进程/标题特征」：WPS 认标题前缀 `WPS Presentation Slide Show` 且进程 `wpp`（WPS 12 的放映窗是 `Qt5QWindowIcon`，宿主进程是 `wpp.exe`，编辑窗才是 `wps.exe` 的 `PP12FrameClass`）；也在 `%LOCALAPPDATA%\Kingsoft\WPS Office\` 下（WPS 默认按用户安装，不写 Program Files）。
- 只有「两个悬浮窗」同时存在**且**有全屏场景才提示——单开一个软件不会被拦。

## 11. 已知限制（0.2.0 新增）

1. **板书保存是界面自动化**：见 §9。ClassInX 大版本升级后建议先 `--probe-classin` 再验收一次。
2. **冲突提示需要「两个悬浮窗 + 全屏」**：希沃白板把悬浮工具栏收起来、或只开了全屏但没悬浮窗时不会提示（这是刻意的，避免误报）。
3. **关闭软件是「先礼后兵」**：先发 `WM_CLOSE`，5 秒不退才 `taskkill /t`；所以「都不保留」可能让画面短暂停留几秒。
4. **弹窗只能在交互会话里出现**：守护跑在 Session 0（静默部署、无人登录）时不会有弹窗，但 `POST /api/action {"action":"conflict-check"}` 仍会返回判定结果，可由 ClassIsland 等外部系统接管提示。
5. **40 分钟冷却按「上次弹出时间」算**：冷却期内即使换了场景也不打扰；需要立刻再提示就用 `force=true`。
6. **自动拉起只能拉起程序，不能替你进课堂**：`save-classin-board` 会启动 `ClassIn X.exe` 并等板书窗口（标题 `Classroom_…`），但账号登录、进入课堂、打开板书必须由老师完成——没进课堂时 ClassInX 停在启动台，此时按 Ctrl+S 只会弹「黑板内容为空」，程序会把提示框关掉并明确告诉你原因，不会假装保存成功。
7. **保存请求是同步的**：带自动拉起时一次请求可能要等几十秒（最长 `launchTimeoutSec` + 保存时间），面板/脚本调用时超时时间要放宽（内置 HTTP 服务的处理预算是 5 分钟，curl 默认 0 也要按需改 `-m`）。
