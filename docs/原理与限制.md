# 原理与限制

## 1. 热点是怎么开的

用 Windows 自带的移动热点引擎（WinRT）：

```csharp
var profile = NetworkInformation.GetInternetConnectionProfile();
var mgr = NetworkOperatorTetheringManager.CreateFromConnectionProfile(profile);
await mgr.StartTetheringAsync();                  // 开
await mgr.ConfigureAccessPointAsync(config);      // 改 SSID/密码
mgr.TetheringOperationalState                     // On / Off / Starting
mgr.MaxClientCount                                // 系统允许的最大客户端数
```

- Win32 程序直接调 WinRT **不需要** `wiFiControl` 清单能力（那个只约束 UWP/AppContainer），所以不做 MSIX 打包。
- `CreateFromConnectionProfile` 必须拿到「有 Internet 的连接配置文件」——这决定了为什么不能把它做成 Windows 服务（见 §4）。
- `netsh wlan hostednetwork` 是另一套东西，Win10 已弃用，Intel AX210 上 `netsh wlan show drivers` 直接显示「支持的承载网络: 否」。本工具完全不用它。

## 2. 8 台上限是怎么破的

`MaxClientCount` 默认 8，是移动热点自身的设计默认值（早期 hosted network 遗留），**不是网卡驱动的硬限**。

- 注册表键：`HKLM\SYSTEM\CurrentControlSet\Services\icssvc\Settings`，值 `WifiMaxPeers`（REG_DWORD）
- 改完必须重启 `icssvc` 服务，让上层重新读

实测（Intel AX210，Win10 19045）：

```text
写入前：MaxClientCount = 8
写入 WifiMaxPeers=16 并重启 icssvc 后：MaxClientCount = 16
```

桌面端「概览」页的「系统上限 16 台」就是读的这个值；「注册表放宽 目标 16」是配置里希望写进去的值。低于目标时会显示黄色告警「系统上限 X 台，低于目标 Y 台」。

> 写入需要管理员：`--fix-peers`（桌面端按钮会提权并弹一次 UAC，结果写到 `C:\ProgramData\ClassroomKit\last-fix.txt`）。

## 3. 「无设备 5 分钟自动关」必须显式关掉

Windows 默认 `IsNoConnectionsTimeoutEnabled() = true`：热点开着但没设备连，5 分钟后自己消失。教室里热点常常在老师进教室前就开着、或者课间没人连，所以必须关：

```csharp
NetworkOperatorTetheringManager.DisableNoConnectionsTimeout();   // 静态方法
```

坑：**这是静态方法**。用实例调 `IsNoConnectionsTimeoutEnabled()` / `GetTetheringCapability()` 会抛 `MethodNotFound`（反射实测），早期版本就是因此调反了方向、热点照旧 5 分钟消失。

## 4. 为什么不做成 Windows 服务

服务跑在 Session 0，没有登录用户；而 `NetworkInformation.GetInternetConnectionProfile()` 和移动热点绑定的是「当前用户的连接配置文件」，Session 0 里拿到的是空 → 起不来。ClassIsland 恰好运行在用户会话里，但它是普通权限、且要等界面和课表加载完（10–40 秒），比开机自启慢得多。

结论：**用户级常驻进程 + 登录自启计划任务**（延迟 8 秒、Users 组、最高可用权限、失败每分钟重试 3 次）。0.8.2 起管理员账户默认提权，标准账户仍以普通权限运行；计划任务也用 `HighestAvailable`，避免开机自启的实例与手动启动的实例权限不一致。代价是「不登录就没有热点」——教室场景里老师一定会登录，可接受。

## 5. 为什么只保留本地 HTTP API

0.8.2 起网页面板已移除，桌面端是唯一的人机界面；但 ClassIsland 插件、脚本和排障仍需要一个本机接口，所以保留 `http://127.0.0.1:36037` 上的 `/api`。

- 不用 `HttpListener`：非管理员需要预先注册 URL ACL，部署多一步、还原卡上还容易丢。
- 不用 Kestrel：自带服务器要多带几 MB 依赖，还要处理绑定与证书。
- 自己写一个只绑 `127.0.0.1` 的极简 HTTP/1.1（一问一答、`Connection: close`、16 KB 请求头上限、1 MB 请求体上限、15 秒超时），令牌鉴权走 `?t=` 或 `X-Token`。
- 除 `/api` 外一律 404，不再有静态文件目录，也就不存在路径穿越和旧页面残留的问题。

API 只在回环上，**局域网里的学生打不开**；它没有远程访问设计，也没有网页界面。

## 6. 稳定性设计

| 场景 | 行为 |
| --- | --- |
| 网卡自己把热点关了 / 被第三方工具关了 | 15 秒巡检发现 `OperationalState != On` → 重新开 |
| SSID 或密码被改 | 对比配置与当前值，不一致就 `ConfigureAccessPointAsync` 改回 |
| 开热点失败 | 退避 60 → 300 → 1800 秒，成功即清零 |
| 网线拔掉 | 状态「等待上行」，不反复重试；插回 15 秒内恢复 |
| 上行是 Wi-Fi | 拒绝开热点（会把仅有的无线占掉），除非桌面端勾了「允许 Wi-Fi 当上行」 |
| 启动了两份 | 全局互斥体 `Global\ClassroomKit.Agent`，第二份发个 `ensure` 就退出 |
| 桌面端按钮点了没反应 | 点按钮会唤醒巡检（信号量），不用等 15 秒 |
| 日志 | 内存环形 400 条 + 按天写盘，保留 14 天，写盘失败不影响守护 |

## 7. 资源占用实测

| 指标 | 数值 |
| --- | --- |
| 私有内存 | 约 56 MB（工作集约 152 MB，多数是共享的运行时页） |
| 空闲 CPU | 60 秒采样 0.06 秒 ≈ 0.1%（单核） |
| 单文件大小 | 约 80 MB（自包含，目标机零依赖；其中约 17 MB 是内嵌的 HarmonyOS Sans 字体） |
| 启动到热点可用 | 约 1 秒（进程内）；登录自启另加 8 秒延迟 |

GC 配置了 `System.GC.ConserveMemory=5`，常年开机不会慢慢涨。

## 8. 已知限制

1. **真实 10 台并发没有实测**：手上没有足够的真实终端。注册表层面 16 台已验证（`MaxClientCount=16`），但网卡/AP 固件在真实并发下的表现要按学校实际设备验收（建议先在一个教室试 10–12 台）。
2. **上限仍受驱动/固件约束**：注册表放宽到 16 不代表任何网卡都能跑 16 台；20 台以上不保证，不建议把 `targetClients` 设超过 16。
3. **不登录就没有热点**：见 §4。
4. **只支持一台机器一个热点**：没有集中管理/批量下发，多教室逐台部署（可用 `rebuild.ps1` + 还原卡策略简化）。
5. **只能走系统移动热点引擎**：不支持 WPA3-only、不支持指定 5GHz 信道。`hotspot.band` 是预留字段，1.0 仍不下发到系统 API：部分网卡的移动热点实现会忽略或拒绝指定频段，写进去反而让热点起不来，所以宁可保持 `auto` 交给系统选。
6. **强力卸载是拉起 BCUninstaller**：BCU 需要自备便携版放到 `BCU\` 子目录（Apache-2.0，可随包分发）；没放时按钮会提示路径。
7. **本地 API 没有远程访问**：设计如此；0.8.2 起连网页界面也移除了，只剩带令牌的 `/api`。
8. **“有 IP 没网关”只在单测里验证过**：这条兜底（专治“学校只给 IP”和默认路由抖动）在真机上需要有第二块没配网关的网卡才能端到端复现，本机没有这种网卡；逻辑由 17 项选择器单测覆盖，真机验收时若遇到请重点看桌面端「概览」页「上行」是否显示“无网关”且热点仍为“运行中”。
9. **无外网兜底不等于能上网**：兜底只是让学生能连上、访问一体机上的课件/共享目录；没有 WAN 就没有外网，桌面端会标注「无外网」。

## 9. 板书自动化为什么是「坐标 + 像素」，以及它有多脆

ClassInX 6.0.9 是 Qt 5.15 应用，UIA 树里一个子控件都没有（`FindAll(Children)` 返回 0），所以拿不到按钮的可访问性对象，只能：

1. 按窗口矩形 + 相对坐标点按钮（`保存至本地` = (667,78)，`保存` = (125,258)……）；
2. 按像素判勾选状态（复选框中心 11×11 取样：有绿填充或亮白勾即视为已勾）。

代价很直白：**换皮肤、改 DPI、按钮移位都会失准**。所以坐标单独存在 `C:\ProgramData\ClassroomKit\ui-recipe.json`，`--probe-classin` 可以重新采样一次；匹配时按 6% 容差容忍小幅缩放，真对不上就明确报「界面可能变了，请重新探测」，不会乱点。速度靠全轮询而不是固定 sleep（实测 1.76 秒，其中 0.8 秒是 ClassInX 自己弹的三个「文件已存在」确认框）。1.0.1 起文件写完后不再立刻结束进程，而是先等这次定位到的保存窗口消失（句柄销毁或不再可见；Qt 对话框接受后常常只隐藏不销毁）：正常情况窗口会自己关，额外耗时通常不到 0.5 秒；窗口赖着不走时最多再等 8 秒，仍可见就保留 ClassInX，不冒截断最后一个文件的风险。1.0.2 起在点「保存」前会重新截屏找绿色按钮并强制面板到前台，点完 1.2 秒没有新文件时补点一次；ClassIsland 的倒计时提醒也会在最后 2 秒先收起，避免置顶提醒层截走点击。

## 10. 冲突提示的判定口径

- **悬浮窗**：ClassInX = 该进程的 `TOPMOST + TOOLWINDOW` 窗口且面积 < 30% 屏；希沃白板 = `EasiNote` 进程的 `LAYERED|TOPMOST` 小窗。
- **全屏**：窗口矩形≈整块屏幕（8px 容差）。WPS 放映**不置顶**，ClassInX 板书全屏也不置顶，所以判定不能只看 topmost，必须按「矩形 + 进程/标题特征」：WPS 认标题前缀 `WPS Presentation Slide Show` 且进程 `wpp`（WPS 12 的放映窗是 `Qt5QWindowIcon`，宿主进程是 `wpp.exe`，编辑窗才是 `wps.exe` 的 `PP12FrameClass`）；也在 `%LOCALAPPDATA%\Kingsoft\WPS Office\` 下（WPS 默认按用户安装，不写 Program Files）。
- 只有「两个悬浮窗」同时存在**且**有全屏场景才提示——单开一个软件不会被拦。

## 11. 已知限制（0.2.0 新增）

1. **板书保存是界面自动化**：见 §9。ClassInX 大版本升级后建议先 `--probe-classin` 再验收一次。
2. **冲突提示需要「两个悬浮窗 + 全屏」**：希沃白板把悬浮工具栏收起来、或只开了全屏但没悬浮窗时不会提示（这是刻意的，避免误报）。
3. **保存后关闭是「等窗口先走」**：文件写完后先等保存对话框消失（句柄销毁或不再可见）；3 秒内没关就发 `WM_CLOSE` 再等 5 秒。只有窗口确实消失才 `Kill(entireProcessTree)`，否则保留 ClassInX 让老师手动关，避免在保存收尾时截断文件。进程名按 `ClassIn X` / `ClassInX` / `ClassIn` 三种都查，不再只认一个名字。
4. **弹窗只能在交互会话里出现**：守护跑在 Session 0（静默部署、无人登录）时不会有弹窗，但 `POST /api/action {"action":"conflict-check"}` 仍会返回判定结果，可由 ClassIsland 等外部系统接管提示。
5. **40 分钟冷却按「上次弹出时间」算**：冷却期内即使换了场景也不打扰；需要立刻再提示就用 `force=true`。
6. **自动拉起只能拉起程序，不能替你进课堂**：`save-classin-board` 会启动 `ClassIn X.exe` 并等板书窗口（标题 `Classroom_…`），但账号登录、进入课堂、打开板书必须由老师完成——没进课堂时 ClassInX 停在启动台，此时按 Ctrl+S 只会弹「黑板内容为空」，程序会把提示框关掉并明确告诉你原因，不会假装保存成功。
7. **保存请求是同步的**：带自动拉起时一次请求可能要等几十秒（最长 `launchTimeoutSec` + 保存时间），桌面端/脚本调用时超时时间要放宽（内置 HTTP 服务的处理预算是 5 分钟，curl 默认 0 也要按需改 `-m`）。

## 12. 「生效科目」为什么只管提醒、不管文件名

课表联动原本是全科生效的：下课后自动保存、板书按科目命名，所有课一视同仁。教室里实际常有「只有物理课才用 ClassInX 板书」这种用法，所以加了 `lesson.subjects`（桌面端「课表与板书」页、插件设置页的「生效科目」）。这里记一下边界，免得后面被当成 bug 改掉：

- **只约束「课后自动保存」这类由课表驱动的动作**：命中白名单才进入倒计时；不命中时 `Evaluate` 直接返回 `subject-skipped`，桌面端和 `--lesson-status` 都能看到原因。
- **不约束板书文件名**：`NameHint` 仍按当前课 / 刚结束那节课的科目取名。手动保存、在 ClassInX 里按 Ctrl+S 时，课表白名单不该是唯一依据；如果文件名也跟着裁掉，老师临时改存一张图就会掉回 `黑板_日期_时间`，反而更难找。改名发生在保存之后，和「提不提醒」本来就是两件事。
- **匹配规则**：去空白、忽略大小写、双向包含（填 `物理` 命中 `物理实验` / `物理/实验`）；空列表 = 全科生效，所以旧配置升级后行为完全不变。
- **已知取舍**：白名单只看 `NextSubject`；课表这一节没填科目名时按「不匹配」处理——宁可少弹一次，也不在没把握的课上弹。

## 13. 界面为什么不是「真 Mica」

0.8.1 的桌面端按 WinUI 3 的视觉语言重做（Fluent 配色、圆角卡片、开关式勾选、InfoBar、设置分组），但**没有**开启 Windows 11 的 Mica 材质。原因是 WPF 里做真 Mica 只有一条路：`WindowStyle=None` + `AllowsTransparency=True` 的分层窗口，代价是整窗失去 ClearType 次像素抗锯齿、透明层带来额外合成开销，长时间开着的一体机上不划算。

实际做法：

1. 用 DWM 的 `DwmSetWindowAttribute` 打开系统圆角（DWMWA_WINDOW_CORNER_PREFERENCE=33）与深色标题栏（DWMWA_USE_IMMERSIVE_DARK_MODE=20）；Win11 生效，Win10 返回失败直接忽略，不报错；
2. 窗口背景用 Fluent 的层次色（`AppBackground` / `Surface` / `SurfaceAlt`），卡片靠 1px 描边和层次色区分，不依赖模糊；
3. 文字仍是 ClearType 渲染，150% 缩放的 1080p 屏上也清楚。

字体方面：HarmonyOS Sans SC（Regular + Semibold）以 WPF `Resource` 形式内嵌进 exe，通过 `pack://application:,,,/ClassroomKit.Agent;component/Assets/Fonts/#HarmonyOS Sans SC` 引用，启动时探测 `GetTypefaces()`，拿不到就退回 `Microsoft YaHei UI` 并写日志。字体不安装进系统，许可与声明随包放在 `licenses\` 下。

## 14. 默认管理员与权限边界

0.8.2 起清单用 `highestAvailable`，不是 `requireAdministrator`：

- **管理员账户**：双击即提权，修复客户端上限、安装护航任务、写 hosts 等不再逐次弹 UAC；
- **标准账户**：程序仍能启动并正常开热点（移动热点本身不需要管理员），需要提权的按钮会提示到管理员账户下操作。用 `requireAdministrator` 会让标准账户完全打不开，教室里反而更糟。

登录自启任务同步改成 `HighestAvailable`，但主体仍是 Users 组，所以标准账户登录时任务以普通权限运行。ClassIsland 插件拉起守护时先 `schtasks /Run /TN ClassroomKit-Agent`，失败再 `ShellExecute --ensure`；前者能复用已注册任务的权限，后者在部分场景下可能弹 UAC。

权限边界要说清楚：

1. 桌面端、托盘、本地 HTTP API 与守护在**同一个进程**里，进程以管理员运行时，这些入口也都在管理员上下文里；
2. 本地 API 只绑 `127.0.0.1`、必须带令牌，除 `/api` 外 404，但令牌就写在 `C:\ProgramData\ClassroomKit\config.json`；
3. 配置目录对 Users 组可写（否则普通权限的守护写不了日志和配置），所以同一台机器上的其他本地用户理论上可以改配置、换令牌；
4. 这是教室一体机既有的本地信任边界，不是远程攻击面；如果以后要收紧，正确做法是把提权部分拆成 `ClassroomKit.Service`（SYSTEM），桌面端以普通用户运行、只通过命名管道调用，而不是继续给整进程加权限。0.8.2 不做这个拆分。

## 15. 网络自我修复为什么只复位无线网卡

0.8.3 的自动修复只针对 0.6.6 报告里的三类现象：热点连续启动失败、有设备连着但上行没有外网、以及「报已开、零客户端、AP 收包不涨」的假启动。做法是复位无线网卡、等驱动重新枚举，再重开热点；不重启电脑、不改系统设置，也不碰有线网卡。

判断依据只有两个：**客户端数**与 **Wi-Fi Direct 适配器的累计收发计数**。不要用 `netsh wlan show networks` 判断自己的热点——STA 扫描看不到本机正在发的 AP。

为什么不修所有网络问题：

1. **上行是有线且没有外网**时，复位无线网卡无济于事；这种情况只提示检查网线或学校网络，避免把「学校断网」误判成热点故障。
2. **空教室整夜零客户端**时，收包同样不涨；所以零客户端且最近 2 小时没有设备连过时不自动复位，避免平白打断希沃传屏等 Wi-Fi Direct 应用。要看这条，得显式打开 `hotspot.restartAdapterOnIdleNoRx`。
3. **认证、DNS、学校网关故障**不在修复范围；复位网卡只能救「热点没真正起来 / 驱动挂死 / 假启动」，救不了上游断网。

安全阀：同一次「上行无外网」最多自动修 2 次，两次自动修复至少隔 15 分钟，每天最多 3 次；手动「检查并修复」不受这些限制，但仍会先判断有没有必要。

代价：修复会短暂断开已连设备（复位后等 10 秒，再等热点进 On），正在传屏或下载的课堂会被打断，所以默认只在有明确异常时触发，且保留开关。

## 16. 课后自动保存为什么这样计时

1.0 把「弹窗提醒」改成「安静地等老师离开，再自己保存」：下课即课间开始，等 **5 分钟**；老师在教室里收东西、擦黑板、和学生说话，通常不会碰鼠标键盘；5 分钟一到，进入 **15 秒**倒计时。倒计时期间任何鼠标/键盘输入都算「老师还在用」，立刻打断，进入 **10 秒**冷却；冷却结束再给 15 秒。

边界这样定：

- **为什么是 5 分钟**：太短会打断老师下课前最后一下操作，太长则离下一节课太近；5 分钟是「老师已经离开、又还没到下一节课」的折中，配置里不再暴露，避免每台机器调得不一样。
- **为什么是 15 秒**：足够让老师看到 ClassIsland 通知并决定要不要打断，又不会让保存拖到上课。
- **为什么点击后只等 10 秒**：老师点一下通常只是关投影、拿东西，不是要改板书；10 秒后重新给 15 秒，仍然保留最后一次反悔机会。
- **为什么上课前 2 分 30 秒就放弃**：再晚保存，ClassInX 保存面板可能正好撞上老师打开课件；宁可这次不存，也不在开课时抢窗口。放学后没有下一节，截止线放宽到 30 分钟。
- **怎么判断「没人」**：`GetLastInputInfo` 取整个交互会话最后一次键鼠输入，不只看本程序窗口；守护跑在 Session 0 或取不到输入时间时，视为「无法判断」，不做自动保存，避免在无人值守时误存。
- **预览不是真保存**：`POST /api/board-autosave action=preview` 只走 15 秒倒计时与打断逻辑，结束时回到空闲，不会调用 ClassInX。

限制：这是「按空闲时间猜老师走了」，不是摄像头或人体感应；老师坐在电脑前只看屏幕、不动键鼠，倒计时仍会走完并保存。真到那一步，保存本身是可撤销的（文件只是多一份），比上课后才想起来没存要好。
