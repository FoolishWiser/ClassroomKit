# 和 ClassIsland 配合

两种接法，按你的 ClassIsland 版本选：

| ClassIsland | 推荐做法 |
| --- | --- |
| **2.1.x（推荐）** | 装 ClassroomKit 插件（`.cipx`）：把课表推给守护（课后自动保存、板书按科目改名并归档），设置页看状态，主界面组件显示「热点 8/16 台」，自动化里上下课直接开/关 |
| 1.6 / 1.7，或不想装插件 | 零代码「自动化」：触发器 + 「运行」行动调 `ClassroomKit.Agent.exe --ensure` |

两种接法都不改变同一件事：**热点逻辑永远在独立的 ClassroomKit 守护进程里**。ClassIsland 崩了、升级了、没启动，教室里的网都不会断。

## 一、装插件（ClassIsland 2.1.x）

### 安装

1. 从 [Releases](https://github.com/FoolishWiser/ClassroomKit/releases) 下载 `ClassroomKit-<版本>.cipx`。
2. ClassIsland →「设置」→「插件」→「从本地安装」→ 选这个 `.cipx`。
3. 重启 ClassIsland（插件程序集在启动时加载）。
4. 「设置」里会多出「ClassroomKit 助手」一页。

插件要求 ClassIsland **2.1.x**（SDK 2.1.0.1，清单 `apiVersion: 2.0.0.0`）。ClassIsland 2.0 之前、1.7 之前的版本装不上，请用下面的零代码接法。

### 插件里有什么

- **设置页「ClassroomKit 助手」**：热点状态、名称、密码、已连设备数、上联网卡、守护版本；按钮「启动热点 / 关闭热点 / 修复连接上限」；「换一个热点名称」可以一键改成电脑名；连接设置里能改地址和令牌（**令牌留空时自动读 ClassroomKit 自己的配置**）。
- **主界面组件「ClassroomKit 助手」**：一行字显示 `热点 ON · CLASSROOM-302 · 3/10`。在 ClassIsland 主界面编辑模式里添加。
- **自动化行动**：「开启教室热点」（守护没跑会先拉起来）、「关闭教室热点」、「保存板书」。配法和普通行动一样：触发器选「上课时 / 放学时 / 应用启动时」，行动选这两个。
- **课表桥**：插件后台每秒最多推一次课表快照给守护（当前科目、下一节是谁、还有多久、上一节是谁），桌面端「课表」「板书」页与课后自动保存都靠它。

### 课表联动：课后自动保存与板书命名

插件装上后，只要 ClassIsland 里**启用了课表**，下面两件事自动生效：

1. **课后自动保存（1.0 起）**：这一节下课、课间开始 5 分钟后，守护通过本插件在 ClassIsland 通知区显示 15 秒倒计时；期间没人碰鼠标键盘就自动保存，有人动就打断、10 秒后再试，上课前 2 分 30 秒仍未存成则放弃。1.1.0 起连堂的中间课间不再保存，等这门课最后一段下课后动作；`lesson.skipBreakNames` 里列出的课间名始终不动作。**倒计时通知依赖这个插件**；插件没装或 ClassIsland 通知被关掉时，自动保存仍在后台计时，只是看不到倒数。
2. **板书命名**：保存板书时用**上一节课的科目**命名，例如 `数学_第3节_2026-11-14_10-05.png`，并存进 `数学\` 子目录。正在上课用当前科目，课间用刚结束的那一节；课表数据超过 2 小时没更新就退回 `黑板_日期_时间`，不瞎猜。模板在桌面端「板书」页或 `boardSave.nameTemplate` 里改。
3. **只对某些科目生效**（可选）：桌面端「课表 → 生效科目」直接勾选（留空 = 所有科目），自动保存就只在这些课上触发。科目清单有三路来源并自动合并去重：插件推来的整份课表科目、守护直接读 ClassIsland 档案（`data\\Profiles\\*.json`，0.6.3 起，ClassIsland 没启动也能读到）、以及你手工添加的名字。匹配是宽松的：去掉空格、不区分大小写，两边任意一方包含另一方也算命中——填「物理」能同时匹配课表里的「物理实验」「物理/实验」。勾了科目、但课表这一节没给科目名时按「不匹配」处理。板书文件名**不受**这一项影响，仍按课表科目命名。

守护侧这次为什么不动作，可以在桌面端「课表」页看到「当前不弹：……」，常见原因：正在上课、已放学、没有课间、连堂还没结束、课间名在跳过列表里、这个课间已经处理过、这节课不在「生效科目」里。命令行 `--lesson-status` 看完整 JSON。

几点边界：

- 课表只用于**提醒与命名**，不影响热点开关；课表读不到时热点照常工作。
- **只在 ClassInX 正在运行时自动保存**（`lesson.onlyWhenClassInBoard=true`），避免每节课都白跑一次保存。
- ClassIsland 1.6/1.7 没有这套插件 API，装不了也拿不到课表：热点与手动保存板书仍可用，只是没有课后自动保存与倒计时通知、文件名也不会按科目改。

### 排错

| 现象 | 原因 / 处理 |
| --- | --- |
| 设置页显示「ClassroomKit 没在运行」 | 守护没启动。点「启动热点」会自动拉起；还不行就看 `C:\ProgramData\ClassroomKit\logs` |
| 提示 HTTP 401 | 先看设置页顶部的「令牌来源」：显示「空」说明没读到守护配置 —— 从 `C:\ProgramData\ClassroomKit\config.json` 的 `token` 复制一次填进去；显示「已读取守护配置」还 401，则检查守护是否换了令牌（桌面端重置令牌后要重填） |
| 插件「概览」打不开 / 说缺少 README | 0.4.0 的 `.cipx` 漏了 `README.md` 与 `icon.png`，升到 0.4.1 重新安装即可 |
| 行动执行后热点没变 | 打开桌面端「自检与日志」页看日志；守护在「等待上行」时不会开热点（网线没插/无外网） |
| 装完插件在列表里看不到 | 检查 ClassIsland 版本；`.cipx` 要选对文件（不是 zip） |
| 桌面端「课表」页一直显示未接入 | ClassIsland 没开、课表没启用，或插件没加载（重启 ClassIsland）；设置页里应能看到课表联动状态 |
| 下课没有自动保存 | 先看桌面端「课表」页的「当前不弹：…」；多半是 ClassInX 没在跑、正在上课、没有课间（放学了）、连堂还没结束、课间名被跳过，或这一节不在「生效科目」里。倒计时通知不出现还要确认 ClassIsland 通知已开启 |

## 二、零代码接法（ClassIsland 1.6 / 1.7）

ClassIsland 1.6/1.7 正式版自带「自动化」：触发器 + 规则集 + 行动，**不需要写插件**。

> 2.0 预览版没有自动化面板；2.1 请用上面的插件。

### 配方 A：ClassIsland 一启动就确保热点（推荐）

1. 打开 ClassIsland →「自动化」→ 新建规则集，命名「确保热点」。
2. 触发器：**当应用启动时**。
3. 行动：**运行**，程序填：

   ```text
   C:\Program Files\ClassroomKit\ClassroomKit.Agent.exe
   ```

   参数填：

   ```text
   --ensure
   ```

4. 如果「运行」行动里有「隐藏窗口 / 不显示窗口」选项，勾上（否则可能闪一下黑框）。
5. 保存并启用。

守护已经在跑时它只发一个「确认开热点」的请求就退出（毫秒级）；守护没在跑时它会把守护拉起来。

### 配方 B：每节课开始时再确认一次

1. 同一个规则集里再加一个触发器：**上课时**（可选叠加「cron」，比如每 30 分钟一次）。
2. 行动同上（`--ensure`）。

这层是兜底：学生把热点关掉、厂商工具清理了后台进程，上课铃一响就恢复。

### 配方 C：放学后关掉（可选）

1. 新建规则集「放学关热点」。
2. 触发器：**放学时**。
3. 行动：运行 `C:\Program Files\ClassroomKit\ClassroomKit.Agent.exe`，参数 `--off`。

第二天登录时，开机自启 + 配方 A 会重新开起来（`--off` 只关热点，不影响守护进程）。

### 验证

1. 桌面端「概览」页显示「热点已开」。
2. 在 ClassIsland 里手动触发一次规则集。
3. 桌面端「自检与日志」页里应出现一条「策略：开启热点」或「已在运行」。
4. 想更彻底：任务管理器结束 `ClassroomKit.Agent.exe` → 触发规则集 → 托盘图标和主界面都应回来，热点恢复。

## 常见坑

- **路径有空格**：`C:\Program Files` 里有空格，零代码「运行」行动可能需要自己加引号。
- **别用 `--on` 代替 `--ensure`**：`--on` 只改策略、不会拉起守护；`--ensure` 才是「确保在跑且开着」。
- **别把 exe 放到用户目录**：一体机多人共用时，别的账号跑不到。
- **ClassIsland 以管理员运行**：没影响，守护是用户级的，管理员进程调它一样能用（走同一个 TCP 端口，天然串行）。
