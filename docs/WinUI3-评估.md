# WinUI 3 迁移评估（1.0 复核）

结论：**0.8.x 继续用 WPF，不整体重写为 WinUI 3。** 现在的桌面端已经按 WinUI 3 的视觉语言重做（Fluent 令牌、圆角卡片、InfoBar、开关式控件、DWM 圆角与深色标题栏），继续迁移能换来的主要是系统原生控件和真 Mica，但代价是重做交付链路、托盘和自绘浮层，功能上不会有新增。1.0 复核后结论不变。等机队和部署方式满足文末条件时再评估。

## 现在的技术底座

- 目标框架 `net8.0-windows10.0.19041.0`，WPF + WinForms（托盘 `NotifyIcon`、冲突提示窗）。
- 单文件、自包含 `win-x64` 发布；交付物是 MSI、绿色 zip 与 ClassIsland 的 `.cipx`。
- 清单 `highestAvailable`：管理员账户默认提权，标准账户仍能启动。
- 自绘标题栏 + DWM 属性（圆角 33、深色标题栏 20）；Win10 上这两项自动失效。
- 界面字体 HarmonyOS Sans 以 WPF `Resource` 内嵌，启动探测失败回退微软雅黑。
- 业务逻辑在 `ClassroomKit.Core`，本地 HTTP API 只绑 `127.0.0.1`，ClassIsland 插件是独立进程。

## 三个选项

### A. 保留 WPF，继续借用 WinUI 3 的视觉与交互（推荐）

不换运行时，只把 WinUI 3 的设计令牌、控件形态和交互习惯映射到 WPF。0.8.x–1.0 走的就是这条路：页面结构、标题栏、设置分组、开关、InfoBar、确认弹层都已按这套语言实现。

- 成本：低，按页面逐步打磨。
- 风险：部分系统行为（真 Mica、系统 ContentDialog、Win11 贴靠布局）只能近似。
- 适合：教室一体机仍以 Win10 为主、要保绿色版和单文件交付。

### B. 整体迁移到 WinUI 3（Windows App SDK）

把 WPF 壳、十个页面、冲突提示窗和托盘全部换成 WinUI 3。业务层（Core、配置、热点、课表、升级）可以保留，界面与宿主层要重写。

主要工作与风险：

1. **交付方式**：Windows App SDK 应用通常走 MSIX，或未打包 + 引导程序；官方不支持把 WinUI 3 应用打成现在这种传统单文件 exe。MSI 自定义动作、绿色 zip、还原卡部署都要重新验证，可能被迫只发 MSIX。
2. **托盘**：WinUI 3 没有 `NotifyIcon`，要用 Win32 `Shell_NotifyIcon` 或第三方封装，菜单、DPI、开机自启、单实例都要重写。
3. **自绘窗口与浮层**：冲突提示窗依赖置顶、全屏判定与鼠标悬停，连接卡、确认层、教程遮罩依赖窗口内图层与键盘处理，这些在 WinUI 3 里都要重新实现并逐项回归。
4. **线程模型**：WPF `Dispatcher` 换成 WinUI `DispatcherQueue`；现有 `MainViewModel` 的大量 `Raise`、异步回填和 `Dispatcher.BeginInvoke` 要逐处核对。
5. **页面与样式**：十个页面 XAML 全量重写，现有 `Styles.xaml` 的 Fluent 令牌可复用，但控件模板、滚动条、下拉框、开关都要按 WinUI 3 重做。
6. **字体与许可**：HarmonyOS Sans 的内嵌方式、pack URI 与回退逻辑要重新验证；WinUI 3 的资源打包与 WPF 不同。
7. **默认管理员**：WinUI 3 未打包应用在提权、启动器与 MSIX 安装场景下的行为要单独验证，不能假设和现在一致。
8. **测试与 CI**：现有 UI 静态断言、单文件发布校验、`windows-latest` 打包链路都要改；还要处理 MSIX 签名与升级。

粗略工作量：界面与宿主层 2–4 周（不含现场回归），且会引入一批与功能无关的回归风险。

### C. XAML Islands / 局部嵌入

只能在 WPF 窗口里嵌局部 WinUI 3 控件，不能把整个壳换掉；还要引入 Windows App SDK 引导程序与窗口消息互操作。对“整体更像 Win11”的收益很小，不推荐。

## 什么条件下重新评估

同时满足这四条再考虑 B：

1. 教室机队以 Windows 11 为主，真 Mica 和系统贴靠有实际价值；
2. 能接受 MSIX 或文件夹部署，放弃“单文件 exe + 绿色 zip”；
3. 愿意重写托盘、冲突窗与自绘浮层，并为课堂场景做一轮完整回归；
4. 能接受默认管理员、单实例、开机自启在 MSIX/未打包两种形态下各验一遍。

在那之前，A 是性价比最高的路线：继续用 WPF 承载业务，把 WinUI 3 的视觉与交互细节补齐。
